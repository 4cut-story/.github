# 성능 개선과 문제 해결

[← 4cut story 소개로 돌아가기](https://github.com/4cut-story)

GPU PC와 운영 환경에서 직접 재고 고친 것들이에요. 항목마다 **문제 → 원인 → 해결 → 전후 비교** 순서예요.

| 모델 다시 올리기 | 컷당 그리기 | 그림 점수 | 말풍선 자리 | 캐릭터 성별·나이 |
| :---: | :---: | :---: | :---: | :---: |
| **86~194초 → 1.2초** | **8.6초 → 2.9초** | **81.4 → 97.5점** | **1.05 → 1.25점** | **틀림 0건** |

<summary><b>속도</b> (8건)</summary>

### 대사 읽기가 멈칫하던 문제

- **문제** 처음 쓰던 GPT-SoVITS가 대사 하나를 읽을 때마다 16~64초씩 멈춰 있었어요.
- **원인** 기본 설정인 CUDA Graph(GPU 작업 순서를 미리 녹화해 두고 다시 쓰는 기능)가 대사마다 길이가 달라 매번 새로 녹화하고 있었어요.
- **해결** CUDA Graph를 꺼서 대사마다 바로 계산하게 했어요.
- **전후** 대사 1줄 16~64초 지연 → **약 2.7초**

### 그림 그리는 시간 줄이기

- **문제** 4컷 그림을 그리는 데 오래 걸렸어요.
- **원인** 이미지 모델은 잡음에서 시작해 그림을 30번 다듬어요. 게다가 메모리를 아끼려 모델 일부를 CPU로 옮겨 가며 그려서, 컷마다 GPU와 CPU 사이 이동이 컸어요.
- **해결** 8번만 다듬어도 되도록 학습된 Lightning LoRA를 얹고, 크기를 768px로 맞춰 16GB 안에 다 올린 뒤 CPU로 옮기는 기능을 껐어요.
- **전후** 30단계 → **8단계, 약 7배 빠르게 (4컷 약 5.6초)**

### 모델 다시 올리는 시간

- **문제** 작업 종류가 바뀔 때마다 1~3분씩 멈춰 있었어요.
- **원인** GPU 한 장으로 받아 적기·LLM·그림 모델을 번갈아 써야 해서, 그림 모델을 내렸다가 디스크에서 다시 읽고 있었어요.
- **해결** 모델을 내릴 때 지우지 않고 PC 메모리(32GB)로 옮겨 두고, 다음 그림 작업에서는 GPU로 옮기기만 해요. 시각 정렬 모델도 언어별로 한 번만 읽어 같은 방식으로 보관해요.
- **전후** 86~194초 → **1.2~1.4초**

### 숨어 있던 13% 느려짐

- **문제** 받아 적기 다음에 그리는 그림만 장당 느렸어요.
- **원인** 화자 분리 모델(pyannote)이 GPU 계산 방식(TF32)을 꺼 놓고 되돌리지 않아서, 같은 프로세스의 그림 모델까지 느린 방식으로 돌았어요.
- **해결** 화자 분리가 끝나면 계산 방식을 원래대로 되돌려요.
- **전후** 장당 1.5초 → **장당 1.33초**

### LLM 호출 동시에 하기

- **문제** 긴 대화는 받아 적은 글의 뒷부분이 다듬어지지 않기도 했어요.
- **원인** 150줄 묶음과 10분 구간을 하나씩 차례로 불러서, 대화가 길면 3분 한도 안에 다 끝나지 않았어요.
- **해결** 글 다듬기는 4묶음씩, 장면 찾기는 모든 구간을 동시에 불러요. 단계마다 걸린 시간과 전체 시간을 로그로 남겨 다음 개선의 근거로 써요.
- **전후** 한 묶음씩 차례로 → **4묶음 동시 · 구간 전체 동시**

### 목록 썸네일 가볍게

- **문제** 피드와 사용자 페이지, 만화함 목록이 열리는 데 오래 걸렸어요.
- **원인** 목록은 첫 컷만 보여 주는데, 썸네일은 4컷 전체를 폭 400px로 줄인 PNG라 한 장에 0.6~2.3MB였어요. 피드 한 쪽(20편)에 수십 MB를 받았어요.
- **해결** 첫 컷만 잘라 폭 480px JPEG로 만들어 저장소에 두고 목록에서는 그 그림만 받아요. 예전 만화는 처음 열거나 2분마다 도는 작업이 채우고, 한 번 만든 썸네일은 브라우저가 일주일 캐시해요. 그림 모델 비교 화면(/lab)도 방식 62개를 처음부터 모두 고르던 것을, 지금 서비스에서 쓰는 방식만 고르게 바꿨어요.
- **전후** 썸네일 한 장 평균 1.9MB → **평균 58KB, 약 33배 가볍게 (피드 20편 합계 약 1MB)**

### 게시물 그림 가볍게

- **문제** 라이브 모드가 기본이 되면서, 게시물 한 편을 열면 휴대폰 데이터로 40MB 가까이 받았어요.
- **원인** 7컷 게시물은 컷 그림과 움직임 그림이 28장인데, 모두 1024px PNG(장당 약 1.4MB)였고 처음 열 때 한꺼번에 받았어요. 캐시도 1시간짜리 private이었어요.
- **해결** web이 권한을 확인한 뒤 그림을 WebP(품질 78)로 바꾸고 화면 폭에 맞는 크기(384·640·1024px)로 줄여 보내요. 바꾼 그림은 원본 ETag와 함께 메모리에 두어 같은 그림을 다시 바꾸지 않아요. 움직임 그림은 지금 컷과 다음 컷 것만 받아요. 로그인하지 않고 받은 그림은 전체 공개라 public으로, 한 번 만들면 바뀌지 않는 컷 그림·얼굴 그림·썸네일은 일주일 캐시해요. AVIF는 WebP보다 35%쯤 더 작지만 인코딩이 5배쯤 느려 쓰지 않았어요.
- **전후** 7컷 게시물 처음 열 때 그림 32장 39.3MB → **그림 17장 약 1.4MB, 끝까지 봐도 약 3.5MB**

### 그림 모델 비교 화면 빠르게

- **문제** 그림 모델 비교 화면(/lab)이 점수표를 보이기까지 6초 넘게 걸렸어요.
- **원인** 브라우저가 GitHub에서 파일 목록을 받은 뒤 방식마다 측정·채점 파일을 하나씩 따로 받아 요청이 127번 오갔어요. 컷 그림은 한 장에 1MB쯤인 원본 PNG였고, 글꼴도 2MB 파일 하나를 통째로 받았어요.
- **해결** web 서버가 측정·채점 파일을 한 번에 모아 5분 캐시해 두고 화면과 함께 보내요. 새 방식이 채점되면 배포 없이 몇 분 안에 나와요. 컷 그림은 칸 크기에 맞춘 WebP로 줄여 보내고 누르면 원본을 열어요. 글꼴은 화면에 나온 글자가 든 조각만 받아요(모든 화면에 적용).
- **전후** 브라우저 GitHub 요청 127번 · 첫 화면 10.8MB → **브라우저 GitHub 요청 0번 · 첫 화면 2.1MB**

### 만화마다 남기는 제작 기록

- **문제** 만화 한 편이 어떤 모델로, 어느 단계에서 얼마나 걸려 만들어졌는지 알 수 없었어요. 그림 모델을 바꿔 시험해도 실제로 올라온 만화와 견줄 기록이 없었어요.
- **원인** GPU 워커는 결과와 함께 쓴 모델 정보와 실행 시간을 보냈지만, 서버가 저장하지 않고 버렸어요.
- **해결** 작업마다 워커가 보낸 모델 정보(그림 모델·양자화·step·해상도·시드·GPU, 컷별 그리기 시간, 모델 올린 시간)와 외부 LLM이 답한 모델을 저장하고, 단계별 걸린 시간·시도 횟수와 묶어 만화를 등록할 때 함께 남겨요. 게시물의 등장인물 아래 '제작 정보'에서 볼 수 있어요. 예전 만화는 남아 있던 단계 기록으로 걸린 시간과 LLM 모델을 채웠어요.
- **전후** 기록 없음 → **만화마다 단계별 모델·시간**

### 뉴스 뒤에서 기다리던 만화

- **문제** 직접 만든 만화가 한 편에 10분 넘게 걸렸어요.
- **원인** RSS 구독으로 뉴스 46편이 한꺼번에 들어왔는데, 모두 같은 차례라 GPU가 먼저 들어온 순서대로 그렸어요. 그림 자체는 4컷 약 165초, 8컷 약 294초로 그대로였어요.
- **해결** 구독이 자동으로 만든 만화의 그림 작업은 낮은 차례로 넣어요. 사람이 만든 만화를 먼저 그리고, GPU가 비면 뉴스를 이어서 그려요. 대사 읽기는 몇 초면 끝나는 마지막 작업이라 뉴스 만화라도 늘 먼저 줘요. 처음엔 대사 읽기까지 낮은 차례로 넣어, 그림 뒤에서 10분을 기다리다 소리 없이 넘어간 만화가 생겼어요.
- **전후** 뉴스 46편 뒤에서 대기 → **사람이 만든 만화 먼저**

### 그래픽 메모리 나눠 쓰기

- **문제** 세 모델 묶음을 한꺼번에 올리면 16GB를 넘어요.
- **원인** 받아 적기 약 7GB, LLM 약 7GB, 그림 약 11GB가 필요해요. 화면 출력 몫으로 약 2GB도 남겨야 해요.
- **해결** 한 번에 작업 하나, 모델 묶음 하나만 올려요. 워커는 지금 올려 둔 모델과 같은 종류의 일을 먼저 받아 전환 횟수를 줄여요. LLM 작업이 이어지는 5분 동안은 내리지 않아요.
- **전후** 합계 약 25GB → **묶음당 최대 약 11GB**

### 남은 메모리 잘못 읽기

- **문제** 메모리가 꽉 찼는데도 모델을 올리려다 멈췄어요.
- **원인** Windows에서는 PyTorch가 다른 프로그램이 쓰는 그래픽 메모리를 빼지 않고 보고했어요.
- **해결** 그래픽카드 드라이버(NVML → nvidia-smi)에서 직접 읽고, 모자라면 '메모리 부족, 다시 시도'로 보고해 작업을 대기열로 돌려보내요.
- **전후** 실제 2.9GB인데 13.7GB로 보임 → **드라이버와 같은 값으로 판단**

### 잘리던 그림 설명

- **문제** 그림에 장면과 동작이 빠졌어요.
- **원인** 이미지 모델은 설명의 앞 77토큰만 읽는데, 한국어로 쓴 외모·장면 설명이 약 274토큰이라 뒤쪽 장면이 잘렸어요.
- **해결** 콘티가 장면과 외모를 짧은 영어로 쓰게 하고, 장면을 외모보다 앞에 둬요. 그림체 문구도 줄였어요.
- **전후** 약 274토큰 → **77토큰 안**

### 누가 말했는지 모르던 말풍선

- **문제** 말풍선만 보고는 어느 인물이 한 말인지 알기 어려웠어요.
- **원인** 말풍선을 화자와 상관없이 첫 대사는 왼쪽 위, 둘째 대사는 오른쪽 아래에 놓고 꼬리도 없었어요. 오른쪽 인물의 말이 왼쪽 위에 붙기도 했어요.
- **해결** 만화마다 인물의 왼쪽·오른쪽 자리를 정하고, 그림·말풍선이 같은 자리를 써요. 말풍선은 화자 쪽에 붙이고 꼬리가 화자를 가리켜요.
- **전후** 자리 고정, 꼬리 없음 → **화자 쪽 + 꼬리**

### 대사에서 튀던 이름

- **문제** 말풍선과 대사에 "하늘", "민지" 같은 이름이 나와 가족 대화가 남의 이야기처럼 읽혔어요.
- **원인** 콘티가 인물마다 가명(나중에는 캐릭터 이름)을 붙이고, 말풍선 앞과 대사 속 부르는 말에 그 이름을 그대로 썼어요.
- **해결** 콘티가 인물마다 호칭(할머니, 손녀, 친구…)을 정하고, 대사·제목·말풍선은 호칭으로 불러요. 남은 이름은 코드로 호칭으로 바꾸고 조사도 맞춰요("하늘아" → "할머니"). 캐릭터 이름과 그림은 만화 아래 등장인물 소개로 옮겼어요.
- **전후** 말풍선에 이름 → **호칭 + 아래 등장인물 소개**

### 컷마다 바뀌던 옷과 자리

- **문제** 두 명이 나오는 만화에서 한 인물의 머리 모양·옷이 컷마다 달라지고, 좌우 자리도 바뀌었어요.
- **원인** 얼굴만 잡는 Plus-Face 어댑터를 써서 옷과 머리는 글 설명에만 맡겼어요. 좌우 자리는 장면 문장에 먼저 나온 인물을 왼쪽에 두어서 문장 순서가 바뀌면 자리도 바뀌었어요.
- **해결** 옷과 머리까지 따르는 Plus 어댑터로 바꾸고, 앞쪽 step은 약하게 뒤쪽 step은 강하게 걸어 장면 구도를 지켜요. 가장 많이 나오는 두 인물은 네 컷 내내 같은 쪽에 세우고 그림 설명에도 왼쪽·오른쪽을 적어요.
- **전후** 얼굴만 참조 → **얼굴·머리·옷 참조**

### 옆 사람에게 번지던 흰머리

- **문제** 할머니와 손녀가 함께 나오는 컷에서 손녀까지 흰머리 노인처럼 그려졌어요. 옷과 안경은 손녀 것이 맞았어요.
- **원인** 머리 색은 그림의 앞쪽 step에서 정해지는데, 그때는 캐릭터 참조를 약하게 걸어서 할머니의 "회색 머리" 설명이 옆 사람에게도 번졌어요.
- **해결** 참조를 강하게 거는 시점을 5번째 step에서 3번째 step으로 앞당겼어요. 4번째로 당겼을 때는 일부 컷에서 아직 은발이 번져 한 step 더 당겼어요. 세기는 GPU PC를 다시 켜지 않고 대화 서비스 설정으로 고칠 수 있게 했어요.
- **전후** 앞쪽 4 step 약하게 → **앞쪽 2 step 약하게**

### 두 명 컷에서 잘리던 장면 문장

- **문제** 조선·무협처럼 그림체 설명이 긴 만화에서 두 명이 나오는 컷은 누가 무엇을 하는지가 그림에 빠졌어요.
- **원인** 이미지 모델은 설명의 앞 77토큰만 읽어요. 그림체와 두 인물의 외모를 적고 나면 조선 예시가 86토큰이라 장면 문장 끝이 잘렸어요.
- **해결** 77토큰을 넘는 설명은 쉼표 뒤에서 75토큰씩 나눠 따로 읽힌 뒤 이어 붙여요. 짧은 설명은 예전과 똑같이 그려요.
- **전후** 앞 77토큰만 → **설명 전체**

### 네 컷이 같은 자세로 나오던 문제

- **문제** 만화 13편 중 5편에서 같은 두 사람이 네 컷 내내 같은 자세로 서 있고 대사만 바뀌었어요.
- **원인** 얼굴과 옷이 컷마다 바뀌지 않도록 네 컷을 같은 시작 노이즈(시드)로 그렸어요. 그래서 구도까지 비슷해졌어요.
- **해결** 컷에 나오는 인물이 모두 캐릭터 참조로 그려지면 얼굴과 옷은 참조가 지키므로 컷마다 시드를 바꿔요. 참조가 없는 인물이 나오는 컷은 예전처럼 같은 시드로 그려요.
- **전후** 네 컷 같은 시드 → **참조 컷은 컷마다 시드**

### 기사와 짝짓기 어렵던 만화 대사

- **문제** 기사로 만든 만화를 보고 원래 기사를 떠올리기 어려웠어요. 비리나 사고 기사도 슬퍼하거나 소식을 전하기만 하는 대화가 됐고, 잘한 일을 다룬 기사도 무엇을 잘했는지가 흐렸어요.
- **원인** 기사 각색은 사실만 가져와 이야기를 새로 지으라고만 해서, 기사 성격에 맞춰 이야기를 어떻게 끌고 갈지 정하지 않았어요. 장면 고르기와 콘티는 기사를 모른 채 웃음·진심 같은 정해진 분위기로만 콘티를 짰어요.
- **해결** 대화를 쓰기 전에 기사 핵심 사실 3~5개와 흐름, 남길 한 줄, 기승전결을 먼저 기획해요. 흐름은 정해진 목록 없이 기사마다 정하고, 사회적으로 잘못된 일은 반드시 풍자로 꼬집어요. 핵심 사실은 숫자를 바꾸지 않고 대사에 모두 넣고, 기획을 장면 고르기와 콘티에 넘겨 말풍선까지 이어지게 했어요. 녹음한 대화도 장면마다 무엇을 어떻게 살릴지 흐름 한 줄을 정해 콘티에 넘기고, 함께 보낸 즐거운 하루는 억지 반전 없이 기록해요. 같은 기사 8편을 다시 만들어 보니 칭찬, 감동의 재회, 셀프 마취 풍자, 되풀이되는 사고 경고, 숫자만 맞춘 가로수 풍자, "그래서 나는?", 티끌 모아 나눔, 알고 맞자처럼 기사마다 다른 흐름이 나왔어요.
- **전후** 핵심 사실 56개 중 51개, 흐름 구분 없음 → **56개 중 55개, 기사마다 흐름**

### 집·카페로 쏠리던 장면 장소

- **문제** 최근 10일 콘티 343편 중 44%가 첫 장소로 집·거실·방·카페였고, 기사로 만든 만화는 74편 중 49%였어요. 재판을 방청한 이야기가 카페에서, 철도 파업 이야기가 거실에서 그려졌어요.
- **원인** 기사를 대화로 바꿀 때 '그 일을 두고 나누는 대화'를 쓰게 해서 뉴스를 전해 듣는 자리(거실, 카페, 식탁)의 대화가 됐어요. 콘티 장소 규칙에도 대화를 나눈 자리와 이야기 속 일이 벌어진 곳을 가르는 기준이 없었어요.
- **해결** 콘티는 이야기 속 일이 벌어지는 곳을 장소로 정하고, 들려주는 이야기는 그 현장을 첫 장소로, 듣는 사람의 반응은 마지막 컷에 둘째 장소로 그려요. 집·거실·카페는 대화에 그 장소가 나오거나 그곳에서 일이 벌어질 때만 써요. 기사 각색은 대화 자리를 사건 현장으로 두어요. 같은 기사 9편을 다시 만들어 보니 법정 방청석, 기차역 대합실, 반도체 시험실, 증권사, 병원 신생아실 앞처럼 이야기에 맞는 곳이 나왔고, 실제로 식당·집에서 나눈 녹음 샘플 5편은 그 자리를 그대로 지켰어요.
- **전후** 기사 9편 중 집·카페 8편 → **0편**

### 그림에 빠지던 장소와 소품

- **문제** 만화 13편 중 5편에서 대화에 나온 장소나 물건이 그림에 없었어요. 한 편은 마지막 컷이 여섯 칸짜리 작은 격자로 그려졌어요.
- **원인** 콘티에는 장면 한 줄만 있어서 장소와 표정이 그림 설명에 들어가지 않았어요. 게다가 그림체에 "단순한 배경", 그리지 말 것에 "자세한 배경"이 들어 있어 소품을 지웠어요.
- **해결** 콘티를 쓸 때 컷마다 장소와 눈에 보이는 물건 2~3개, 인물별 표정을 따로 적게 하고 그림 설명 뒤에 붙여요. 배경 설정은 어지러운 배경만 막도록 바꾸고, 그리지 말 것에 여러 칸·격자를 더했어요.
- **전후** 장면 한 줄 → **장면 + 장소·소품 + 표정**

### 한 컷에 같은 사람이 두 번 나오던 문제

- **문제** 만화 13편 중 3편에서 주인공과 캐릭터 DB에 없는 다른 사람이 함께 나오는 컷에 주인공이 두 번 그려졌어요.
- **원인** 혼자 참조된 인물은 그림 전체에 캐릭터 참조를 걸었어요. 그래서 옆 사람 얼굴과 옷까지 주인공을 따라갔어요.
- **해결** 장면에 다른 사람이 나오면 참조 인물의 참조를 그림 가운데에만 걸어요. 가장자리에 선 사람은 장면 설명대로 그려져요.
- **전후** 그림 전체에 참조 → **다른 사람이 있으면 가운데만**

### 고친 효과를 같은 조건으로 재기

- **문제** 그림을 고친 뒤 좋아졌는지 나빠졌는지 비교하기 어려웠어요. 같은 녹음을 다시 올려도 매번 다른 만화가 나왔어요.
- **원인** 그림 시드가 대화마다 새로 붙는 번호로 정해지고, LLM의 장면·콘티 답도 부를 때마다 조금씩 달랐어요.
- **해결** 시드를 대화 내용으로 정하고, 같은 입력의 LLM 답은 저장해 두고 다시 써요. 고정한 시험 세트를 고치기 전후로 그려 나란히 놓고 채점하고, 점수가 오를 때만 수정을 남겨요.
- **전후** 같은 녹음도 매번 다른 만화 → **고친 부분만 달라짐**

### 거칠던 선과 뭉개진 얼굴

- **문제** 선이 흐리고 얼굴이 뭉개진 컷이 많았어요.
- **원인** 적은 단계로 그리는 설정(guidance 0)에서는 '그리지 말 것' 문구가 그림에 쓰이지 않아요. 그런데 품질을 올리는 좋은 말은 하나도 없었어요.
- **해결** 모든 그림체 문구 바로 뒤에 "high quality illustration, crisp clean lineart, well-drawn faces"를 붙였어요.
- **전후** 화질 1.35점 (2점 만점) → **화질 1.55점**

### 그림 모델 바꾸기

- **문제** 핵심 물건(망원경, 양말, 팻말)이 그림에 나오지 않고, 그림이 흑백 스케치처럼 거칠었어요.
- **원인** 프롬프트에 물건을 정확히 넣어도 SDXL 기본 모델은 작은 물건과 얼굴을 잘 그리지 못했어요. 그림 쪽에서 인물 수를 맞추려던 다시 그리기·뼈대 그림은 오히려 점수를 낮췄어요.
- **해결** 같은 SDXL 계열이라 참조 인물 모듈을 그대로 쓸 수 있는 일러스트용 모델 DreamShaper XL Lightning으로 바꿨어요.
- **전후** 시험 묶음 81.4점 → **83.7점, 컬러 만화 그림**

### 글을 더 잘 읽는 그림 모델로

- **문제** 설정을 다섯 번 바꿔도 점수가 83점 안팎에서 멈췄어요. 콘티의 행동과 물건이 빠지고, 한 컷의 두 인물이 한 사람으로 섞였어요.
- **원인** SDXL은 CLIP 글 인코더로 장면 설명을 읽는데, 긴 문장에서 누가 무엇을 하는지까지는 잘 따르지 못했어요.
- **해결** 긴 문장을 읽는 T5 글 인코더를 쓰는 FLUX.1-schnell로 바꾸고, 16GB GPU에 맞게 4비트로 줄였어요. 실패하면 SDXL로 저절로 되돌아가요.
- **전후** 시험 묶음 82.8점 → **87.9점**

### 다른 사람을 가리키던 말풍선

- **문제** 손주를 왼쪽, 할아버지를 오른쪽에 세우라고 했는데 할아버지가 왼쪽에 그려져, 말풍선 꼬리가 다른 사람을 가리켰어요.
- **원인** 말풍선은 정해 둔 자리를 따르는데, 그림 설명 순서와 참조 가림판만으로는 그림 모델이 좌우를 늘 지키지 않아요.
- **해결** 두 명 이상 서고 누가 말하는 컷은 다 그린 그림을 Claude에게 보여 주고, 인물마다 실제로 선 쪽을 받아 말풍선을 그 쪽에 붙여요. 답이 이상하거나 부를 수 없으면 정해 둔 자리를 그대로 써요.
- **전후** 말풍선 1.05점 (2점 만점) → **말풍선 1.25점**

### 얼굴과 물건을 가리던 말풍선

- **문제** 얼굴 위에 둔 말풍선이 인물의 눈과 머리를 가리고, 아래에 둔 말풍선이 국밥 그릇이나 휴대폰처럼 이야기에 중요한 물건을 가렸어요.
- **원인** Claude가 알려 준 얼굴 가운데가 실제보다 아래(입·턱 쪽)인 일이 잦은데, 얼굴 자리를 작게 잡고 그 바로 위에 붙였어요. 물건은 피할 자리로 보지 않았어요.
- **해결** 얼굴 자리를 얼굴 높이의 두 배로 넓히고 머리카락 쪽으로 더 늘렸어요. 얼굴 위 말풍선은 얼굴에서 더 띄워요. 그림을 읽을 때 가리면 안 되는 물건 자리도 세 개까지 받아 얼굴처럼 피하고, 정해 둔 자리가 모두 걸리면 컷 전체를 훑어 빈 자리를 찾아요. 얼굴 아래 몸통보다 얼굴 옆 벽을 먼저 쓰고, 넓은 말풍선이 들어갈 곳이 없으면 폭을 좁혀요.
- **전후** 눈·머리·그릇을 가리던 말풍선 → **얼굴과 중요한 물건을 피한 말풍선**

### 두 명 컷에 사람 수가 틀리던 문제

- **문제** 두 사람 컷에 네 명이 그려지거나 한 명만 그려졌고, 여자 두 사람 중 한 명이 남자로 그려지기도 했어요.
- **원인** 여럿이 나오는 컷에 "two people"이라고만 적었어요. 이 말은 남녀 한 쌍 쪽으로 끌고, 나이·성별은 인물 줄에만 있었어요.
- **해결** 컷 인물 모두의 외모 첫 마디가 나이·성별이면 "a young woman and an old man"처럼 왼쪽부터 세어 적고, 뒤에 "side by side, both fully visible"을 붙여요. 동물 테마는 종으로 세요.
- **전후** "two people" → **왼쪽부터 나이·성별로 세기**

### 흑백 신문 테마의 줄무늬와 망점

- **문제** 흑백 신문 테마 컷의 배경에 스캔 줄 같은 가로줄과 망점이 깔리고, 겹쳐 비친 얼굴과 거꾸로 된 글자가 나왔어요.
- **원인** 흑백 그림을 그림 모델에 바로 시키면 잡티가 생겼어요. '그리지 말 것'에 줄무늬를 더해도 이 설정에서는 쓰이지 않았고, 그림체 문구를 바꿔도 점수가 그대로였어요.
- **해결** 옅은 색 평면 칠로 그리고, 한 장으로 합치기 직전에 컷을 흑백으로 바꿔요.
- **전후** 화질 1.0점 (2점 만점) → **화질 약 1.3점**

### 흑백으로 쏠리던 기사 만화

- **문제** 피드에 올라온 기사 만화의 절반 넘게 흑백으로 나왔어요.
- **원인** 그림 문구가 아니라 테마 고르기가 쏠렸어요. 장면을 고르는 LLM 지시에 "풍자 흐름이면 흑백 신문 테마가 어울린다"가 있었는데, 사회 문제 기사를 모두 풍자로 각색하도록 바꾸면서 사회면 기사가 거의 다 흑백 신문 테마로 갔어요. 테마 설명도 흑백 신문 테마를 "풍자, 회사·사회 이야기"로 넓게 적어 두었어요.
- **해결** 풍자와 흑백 신문 테마를 잇는 문장을 빼고, 흑백 신문 테마는 정치·행정을 꼬집는 시사 만평이 꼭 어울릴 때만 고르게 했어요. 뉴스·사회 이야기와 풍자는 기본이 일상 웹툰 테마예요.
- **전후** 기사 만화 39편 다시 고르기: 흑백 11편 → **3편**

### 짧은 대화가 '장면 없음'으로 끝나던 문제

- **문제** 30초 남짓한 웃긴 대화 두 편이 "만화로 만들 장면을 찾지 못했어요"로 끝났고, 다시 올려도 같았어요.
- **원인** 장면을 고르는 LLM 지시에 '특별한 순간이 없으면 빈 목록이 낫다'가 있어서, 짧은 대화에서는 빈 목록을 냈어요.
- **해결** 구간이 하나뿐인 짧은 대화에서 장면이 없으면, 사용자가 만화로 만들려고 녹음한 대화라는 말을 붙여 한 번 더 물어요.
- **전후** 두 편 모두 장면 없음 → **두 편 모두 게시**

### 빈 말풍선 막기

- **문제** 말풍선이 하나도 없는 컷이 나왔어요.
- **원인** 컷마다 대사를 0~2개 허용했고, 장면 밖 대사를 걸러 내다 컷의 대사가 모두 지워져도 검사를 통과했어요.
- **해결** 컷당 대사를 1~2개로 정하고, 빈 컷은 장면 대화에서 아직 안 쓴 실제 말로 채워요. 다듬은 대사가 비거나 40자를 넘으면 원래 말로 되돌려요.
- **전후** 빈 컷 발생 → **빈 컷 0**

### 캐릭터 찾기 기준 정하기

- **문제** 남자 인물에 여자 캐릭터가, 어른에 아이 캐릭터가 붙기도 했어요.
- **원인** 좌표 거리는 머리색·옷 색 같은 낱말에 끌려서, 성별·나이가 다른 캐릭터를 아주 가깝다고(0.1 안쪽) 내놓기도 했어요.
- **해결** 테마 7개, 여러 문장 형식, 한국어, 캐릭터가 없는 질문까지 1,288개 문장으로 거리를 재서 기준을 0.30으로 정했어요. 가까운 후보 50명 중 외모 첫 마디(성별·나이·동물)가 맞는 캐릭터만 써요.
- **전후** 성별·나이 틀린 결과 발생 → **틀림 0건, 맞는 문장 99% 이상 찾음**

### 그림은 여자, 목소리는 남자

- **문제** 정비소 만화의 안내원이 그림에서는 여자인데 대사는 남자 목소리로 나왔어요.
- **원인** 콘티는 안내원을 남자로 적었고, 긴 생머리 남자 캐릭터(young man, long black hair)가 붙었어요. 그림 모델은 여자처럼 보이는 참조 그림을 따라 그렸고, 목소리는 콘티 성별대로 골랐어요. 일상 참조 그림은 성별과 상관없이 머리 모양을 골라 그려서, 참조 그림 1,013장의 목 옆 머리카락을 재 보니 긴 머리로 그려진 남자 58명(모습 글에는 모자만 있고 그림에는 긴 머리가 있는 24명 포함)과 남자처럼 보이는 짧은 머리 여자 52명이 있었어요.
- **해결** 이 110명은 캐릭터 찾기에서 빼고(지우지 않고 꺼 둠), 긴 머리 남자·짧은 머리 여자 모습은 콘티가 같은 머리 길이를 말했을 때만 써요.
- **전후** 성별과 반대로 보이는 캐릭터 110명 → **0명 (캐릭터 1,013명 → 903명)**

### 역할에 맞는 옷으로 그리기

- **문제** 무명용사의 묘를 지키는 상병 경비병이 크림색 스웨터 차림으로 그려졌어요.
- **원인** 캐릭터가 붙으면 그림 글을 캐릭터 모습(young man, short black hair, cream sweater)으로 바꾸면서 콘티의 제복 글을 버렸어요. 군인처럼 캐릭터 DB에 없는 역할에는 평상복 캐릭터가 붙을 수밖에 없었어요. 게다가 예전에 IP-Adapter 특징을 계산해 둔 캐릭터는 특징 파일만 넘어가, 참조 그림을 그대로 받는 FLUX.2 klein이 참조 없이 그렸어요(이 만화 9컷 중 6컷).
- **해결** 콘티가 인물마다 역할 옷 칸(costume)에 역할·직업·신분 때문에 꼭 보여야 하는 옷을 적어요(예: olive green military uniform, combat helmet). 예전 콘티는 외모의 제복·가운·갑옷 마디를 역할 옷으로 봐요. 그 옷을 입은 캐릭터(경찰관, 의사 등)가 거리 안에 있으면 먼저 쓰고, 없으면 가장 닮은 캐릭터의 참조 그림에서 얼굴·머리만 남겨 넘기고 옷·모자 글은 역할 옷으로 바꿔요. 이런 인물의 소개 그림은 캐릭터 그림(평상복) 대신 컷에서 자른 얼굴을 써요. 참조 그림은 특징 파일이 있어도 늘 넘겨요.
- **전후** 역할 옷 대신 캐릭터 평상복 → **모든 역할에 콘티의 역할 옷**

### 대사 다듬기

- **문제** 받아 적은 말을 그대로 쓰면 오타와 어색한 말이 말풍선에 남았어요.
- **원인** 음성 인식은 잘못 들은 낱말과 띄어쓰기 실수를 남기고, 테마와 상관없이 같은 말투로 대사가 나왔어요.
- **해결** 그리기 전에 받아 적은 글을 먼저 다듬고, 콘티에서 테마별 작가 역할·말투·사투리를 입힌 뒤 맞춤법까지 고쳐요. 원래 말은 따로 보관해 대조에 써요.
- **전후** 받아 적은 말 그대로 → **테마 말투 + 사투리 + 맞춤법 교정**

### 비어 있던 등장인물 그림

- **문제** 게시물 아래 등장인물 소개에서 일부 인물이 그림 없이 회색 칸으로 보였어요. 무협 만화의 아이 인물처럼 같은 만화를 다시 만들어도 늘 같은 인물이 비었어요.
- **원인** 소개 그림은 캐릭터 DB에서 찾은 인물에게만 있었어요. 무협·조선 그림체는 참조 그림의 아이가 어른으로 그려져 있어 아이 인물은 일부러 캐릭터 없이 그리고, 외모가 맞는 캐릭터가 없는 인물도 있어요. 저장소에서 그림을 못 불러온 것이 아니라 처음부터 연결된 그림이 없었어요.
- **해결** 말풍선 자리를 맞출 때 Claude가 알려 준 얼굴 위치로, 그 인물 얼굴이 가장 크게 그려진 컷을 골라 얼굴과 어깨가 들어가는 정사각형(256px)으로 잘라 소개 그림으로 써요. 얼굴이 너무 작게 그려진 컷만 있으면 회색 칸으로 둬요. 컷 그림이 남아 있던 예전 만화도 한 번 채웠어요.
- **전후** 캐릭터 DB에 없는 인물은 빈칸 → **만화 컷에서 자른 얼굴 그림**

### 16GB GPU에 맞는 그림 모델 고르기

### 콘티를 칸 나눈 틀로 받기

- **해결** 게시물·사용자·캐릭터·배경음 페이지는 서버가 로그인 없이 내용을 읽어 제목·설명·대표 주소(canonical)·공유 그림(첫 컷)을 HTML 머리말에 넣어요. 전체 공개 게시물·캐릭터·배경음을 모은 사이트맵을 요청 때 만들어 한 시간 두고, 로그인해야 보이는 화면과 팔로워 공개 게시물은 검색에서 빼요. 게시물·사용자 페이지에는 구조화 데이터(JSON-LD)를 붙였어요.
- **전후** 페이지 제목 1가지, 사이트맵 없음 → **페이지마다 제목·공유 그림, 사이트맵 주소 4,807개**

### 배포 중에 끊긴 대사 쓰기

- **문제** 서버를 새로 배포한 직후 만든 만화는 대사가 Claude가 아니라 GPU PC의 로컬 모델로 써졌고, 몇 분 더 걸렸어요.

- **해결** 내려가는 서버는 하던 대사 작업의 임대를 바로 끝내고, 끊긴 호출을 실패로 보지 않아요. 다음 서버가 30초 안에 그 작업을 거둬 Claude로 이어 써요. GPU 워커는 Claude와 Gemini가 모두 실패했을 때만 대사를 써요.
